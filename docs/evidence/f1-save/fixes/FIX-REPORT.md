## Review findings

| Finding | Fix and verification |
| --- | --- |
| P1-1 export blocked by flush flags | Export attempts to drain/fold, then validates and returns the latest accepted state regardless of admission/Library/write flags. It explains when device persistence failed. Strict Library flush stays strict. Regression tests cover all three flags. Revision metadata growth also cannot publish an oversized accepted state during a fold. |
| P1-2 routine full-save preservation | Challenge start/finish and Cove add/select use atomic envelope writes without whole-save recovery copies. Discard writes only its session into eight rolling slots (at most 32,768 session bytes), outside the old build's recovery namespace. Full preservation remains for migration, restore, person removal and assignment. Folded rows are deleted, not archived. Forty native/web cycles retain only the original recovery copy; twelve Store rounds retain the exact pre-update v2 original. |
| P1-3 moves dropped during I/O | Moves accept synchronously before any await, with all owner/epoch/round/revision guards. Per-game/base latest-wins workers return durability promises. One hundred rapid moves end with durable revision 100 and fewer than 100 writes. A held write does not lose sound/settings changes. A failed write keeps accepted state in memory and gives an explicit retry/export error. |
| P2-1 migration window/recovery text | Canonical empty dares are `''`; the five-person fixture migration grows by 916 bytes rather than 4,336. The 1,998,000-byte fixture upgrades. A separately frozen 1,999,990-byte fixture preserves its original and explains export, management in the previous build, or a smaller backup. Library invalidity has its own message. |
| P2-2 limit refusals | `ChallengeRefusal`/`challengeAttempt` distinguish full save, session budget, learner ceiling and stale work. Store messages explain the action; terminal refusal keeps the paused session and accepted disk state. Regressions cover all three capacity refusals. |
| P2-3 undo/audit conflict | FND-15 revision 2 uses axis-locked paint strokes, exact previous values, a two-byte interval header, a 1,960-byte ring and oldest-whole-stroke eviction. Uniform prior values retain 512 strokes; the exact worst-case guarantee is 217 nine-byte strokes. **218 × 9 = 1,962**, so the review's 218 claim cannot fit the mandated ring. No edit is refused by a full ring. Audit events use 0…9,999 and are never silently dropped. Codec registration rejects wrapper + draft + undo + full-audit allocations above 4,096; full checkpoint-class encodings pass the measured budget proof. |
| P2-4 Together | An existing eligible partner is checked at start. Solo can confirm `null → partner` on the terminal transition only. Cove-only partners cannot hold School banks. Existing removed partners receive no credit; an invalid/full partner record cannot block the starter's finish. Tests cover Together-at-finish, missing partners and Cove-ineligible partners. |
| P2-5 move cost/connections | Moves validate the changed session only, updating a cached learner byte count by the session delta. Boundary/load checks still validate the whole record. Native draft writes use one guarded SQL upsert on the shared connection, retaining exact base/id/ordinal/revision guards. The regression measures one changed-engine validation and no transaction connection per 25 row writes. **Oldest-iPad latency remains unmeasured**; no native timing claim or FND-03 acceptance is made. |
| P2-6 frozen corpus | Added, never regenerated, shipped-source fixtures with advanced/helped School rounds, advanced classics/boards/activities, paused Reef placements, Arcade/School stars, earned items, Library drawing/story content, word/race records and pending earlier work. The shipped migration output is frozen too. The permanent gate compares the whole legacy object, beyond the five previously checked slots. Existing frozen files and receipt are unchanged. |
| P2-7 append-only catalog | Bank length, ordered ordinals, rules, hashes, awards and eligibility are immutable; new content gets a new slot. Registration checks the committed manifest. The build gate checks every prior committed generation, rejecting changed length/hash/order and accepting a new slot. It rejects shallow history, and CI now fetches full history. F2 must populate the manifest with its generated catalog. |
| P3-1 lost acknowledgement | Terminal write rejection reads back the durable head. An exact committed candidate is published; an unreadable head blocks further writes pending recovery. A later ordinary persist cannot erase the credited finish. |
| P3-2 canonical order | Start sorts game IDs by code units, matching validation. A punctuation-ID regression passes. |
| P3-3 repeated registration | Equivalent bank/dare data and equivalent codec implementations can register again; the original frozen definitions remain registered. Changed meanings require new slots/codec IDs. |
| P3-4 bad-row repeat preservation | Native quarantine preserves and deletes the row in one transaction. Web preserves first, deduplicates exact bytes, then deletes. Rehydration no longer repeatedly archives the same rejected row. |
| P3-5 downstream gaps | Starting a Challenge now writes Seen. Explicit discard preserves an exhausted attempt in the bounded session ring before the next ordinal is launched. **Deferred:** F2 must put first Two Ways solution hashes into its exact engine launch payload and prove that adapter; no production adapter exists in this slice. The unused generic `appendUndo` utility remains for adapter work because removing it fixes no runtime defect and could disrupt parallel consumers. The contract states these boundaries. |
| P3-6 transaction description | Documentation and the Node harness now use `BEGIN`, matching the SDK's boundary transaction behavior; they no longer claim `BEGIN EXCLUSIVE`. Draft moves use one guarded statement, and Store serialization supplies ordering. |
| P3-7 full-envelope native parse | Callers pass revision/folded-session metadata to the adapter. Native envelope writes no longer parse the whole save to obtain the generation. Only small draft rows are parsed when deciding whether they were folded. |
| P3-8 maximum-size proof | Context IDs are capped at 16 characters before any production content registration. The new proof fills all 64 practice rows, all bounded working sets, maximum references, 80-character game IDs, 100-character round IDs, maximum ordinal/revision widths and full paused allocations.
