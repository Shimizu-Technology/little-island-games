# Local learner saves

Program 4.0 uses save envelope version 3 with required validated `profiles.version: 2`, `cove.version: 1` and an envelope `saveRevision`. Envelope-1 and envelope-2 backups remain importable through one validated migration. The stable 3.0.x branch continues to write envelope 2 / profiles 1; program code must not reach main before the program acceptance gate. A missing profile namespace cannot be mistaken for a valid older empty save, and older app versions reject the new envelope while preserving its bytes. Backups include every learner, Family practice, shared device settings, earlier family history and pending older-work assignments.

`profiles.people[id]` stores that learner’s paused learning, classic, board and activity rounds; word and race records; favorites, recents and learning coaching; and School completion records. Houses, appearance, badges, Arcade and Library remain in their existing learner namespaces. Every learner, including Family, also has required `challenge` progress. Top-level game fields and `challenge` are only the active learner’s runtime view. A serialized top-level Challenge copy is rejected. `encodeSave` writes canonical slots once; `parseSave` validates each slot with the existing real engine validators and reconstructs the selected view. Unknown versions, invalid slots, owner mismatches, duplicate live owners and partial profile sets fail through normal recovery.

## Upgrade and older work

Migration validates the original first and never mutates it. Load and restore preserve exact originals before publishing a new shape. Learning rounds retain `round.learner`, or Family practice when missing. A matching classic/board/activity `roundOwners` tag preserves the known owner. Unmatched rounds go to the assignment bucket. Unowned learning also retains an assignment copy; assigning it removes the matching Family live round, so it never becomes two children’s live work.

The grown-up Settings gate contains **Whose earlier work is this?** Before the gate, a short line says older work is waiting. An old learning round is offered only while it is still unfinished in Family practice. A grown-up chooses an owner, or **Not needed**, for each old round, the old device-wide Explore history, practice signals, and favorites/recent places. Assignment first keeps a whole-device recovery copy. It refuses to replace a different target paused round. Library assignment adds saved/recent discoveries, preserves policy and newer fields, and fills old models/search context only into a Library created by this migration that the child has not edited. The exact old Explore archive stays available. Names and active selection never establish ownership. Existing badges stay as saved.

Older word and race aggregates are labeled **Earlier family records**. They cannot be reliably split, so they are neither divided nor copied into personal records. The Family free-play score board stays shared.

Reward backfill follows the same rule. When a newer catalog ties a new item to a badge a child already holds, load and restore add it, and older builds then reject that save. So any load or restore that changes a learner's home or badge ledger first keeps the exact incoming bytes in Previous saves, including saves already on envelope v3. A save with nothing to change makes no copy and writes nothing. To roll back, the older build opens to recovery: start fresh there, which keeps the newer save, then restore the pre-update copy from Previous saves. Work done after the update stays in the newer copy. Backups exported after the update cannot be opened by the older build. Repeated load of an unchanged envelope-3 save makes no copy and writes nothing.

## School levels and stars

All five levels stay open. The selected level and completed levels are shown separately. Each learner/game/level record stores best earned stars, completed and independent counts, bounded independent days and deduplication round IDs.

- One star: finish a round, including help or shared play. Family practice is shared, so it earns one star at most.
- Two stars: finish an independent solo round.
- Three stars: finish independent solo rounds on at least two distinct days. The days need not be consecutive.

There is no timer, speed threshold, penalty or automatic advancement. Reading stays untimed. Existing engine help/miss flags, growth clean history, non-winning Reef Race and vocabulary browsing rules determine independence. Unknown old help history earns completion only. Stars never decrease. The result screen shows what the round earned: nothing for a lost round, one star for a helped round, and the level's best for independent work.

Backfill uses actual completed rounds and exact `completed-round` notes. A remembered setup choice, warm-up or aggregate total cannot prove completion. Old notes do not pair assistance and dates with each round, so they never invent third-star dates. Old totals remain intact. New readiness evidence uses `think.level-round-v2`; optional warm-ups retain practice and badge rewards under a separate summary key and do not earn School completion or next-level invitations.

## Ownership and replacement

Switching, restoration, assignment and learner removal advance the callback epoch. Captured classic callbacks check that epoch; learning/activity/board/Arcade writes also check the expected round or learner. Views select only the active profile. Result credit follows an accepted owned transition, and rejected Arcade results show a recoverable Retry.

Removing a learner removes their profile slots, learning notes, Library, appearance, badges, earned items, whole house and Arcade progress. Other learners, earlier family records and the shared Family free-play board remain. Family practice cannot be deleted. Previous saves is a whole-device recovery copy: restoring it replaces all learners’ newer work.

The 2 MB UTF-8 save limit and the shared 1 MB Library limit still apply. Admission failure preserves the last accepted state and reports the error. More profiles do not increase device storage capacity. Native SQLite/Files transport and family-device acceptance are verified separately by the lead.


## Challenge, Cove and drafts (program 4.0)

[The frozen contract](SAVE_CONTRACT.md) defines all seven three-bit completion states, monotonic merge, separate permanent A/B awards and the append-only 4,096-slot dare bitmap. A helped replay never downgrades independent work. Optional bests, recent selections and signals may evict; earned facts never do. Legacy School stars do not invent Challenge marks. Legacy learning, Hall and Arcade rounds retain their original engines and rules.

Challenge caps are 104,000 UTF-8 bytes per learner (8 paused games, 32 signals, 256 numeric bests) and 72,000 bytes for an entire Cove-only person (4 paused games, 8 signals, 128 bests). Cove-only people have a name and Cove progress, up to four outside the five-learner cap. They receive no house, appearance, School or Library record, and never enter the child learner list. Family remains undeletable. Removal changes only the named record and crosses the callback epoch; a removed Together partner receives no later credit.

Together is an engine-validated terminal result credited to both surviving participants in one durable replacement. It changes no School stars, badges or personal offer signals. The starter owns the paused board. No result is shown as credited until preservation and the replacement succeed. A saved credited result cannot credit again. Unknown content, codecs, hashes, owners, rules or evidence enter recovery with original bytes kept. Real-time Arcade physics is never a resumable Challenge session.

F2 supplies immutable banks, dare registrations and exact pure-engine codecs through `registerSaveContent` before hydration. The production catalog is intentionally empty in F1, so no unimplemented game becomes visible or writable. Each codec validates its payload and recomputes terminal truth; it also proves a legitimate initial state and that a later draft extends earlier assistance/audit evidence. The generic checkpoint shape validator cannot certify a game result.

Accepted moves write a small complete row naming envelope revision, owner, game, round, ordinal and action revision. Full-envelope writes happen at start, finish, explicit discard/replacement, pause, export and lifecycle boundaries. The draft write promise is the durability acknowledgment. This is not a claim about OS-kill timing before that promise resolves; action-to-durable-write timing still needs the oldest physical iPad. Never call the full-envelope writer from a drag frame.

Native rows and envelope boundaries use exclusive SQLite transactions. Web boundaries preserve rows before the atomic active-envelope write; a small head cache is repaired from the authoritative envelope after interruption. Obsolete rows are preserved and never applied to a different base. A newer valid row may extend only an existing matching owned round. Restore rekeys the imported envelope, replaces its draft generation and advances the epoch. Export drains queued writes and folds accepted rows into one fully validated envelope first; `store.backup()` returns that coherent snapshot.

A full undo ring drops its oldest delta, never the canonical draft. Check/help/hint/reset audit events are never dropped. Replay games and checkpoints require exact adapter codecs. The contract records the unresolved 4,096-byte / arbitrary multi-cell stroke undo conflict; fixed-width delta capacity is not proof of arbitrary-stroke history.

## Launch, notices and error boundaries (program 4.0)

**Set-aside notices.** A save can name puzzle content this build doesn't have (another dev or TestFlight build, a rollback, a bank whose size changed). Before validation, load takes those paused rounds and marks rows out of a copy so launch still reaches the app. Only well-formed entries are taken out; damage of any other kind goes through preserve-and-recover. Any set-aside forces `preserveAndReplace`, so the exact original bytes are kept in Previous saves before the new save is written. The person it happened to sees one line naming the games, with **OK** to put it away. Nobody else sees it.

The notices live in their own row: `set-aside-notices` in SQLite, `little-island.set-aside-notices` on the web, holding `{ version: 1, items: [{ owner, games, marks }] }` with at most 64 items and one per owner. The row changes in the same write as the save it describes: `EnvelopeWrite.notices` replaces it, and `null` clears it inside the native exclusive transaction. **OK** rewrites the row on the Store's write queue, so it can't cross a save that rewrites it. A missing or malformed row reads as no notices, and notices for owners no longer in the save are dropped. A failed *read* is never treated as empty: it is retried once, and a second failure opens Recovery with "Your island couldn’t finish opening. Your saved work is kept. Try opening again." without replacing the save or the row. Restore and Start fresh clear the row in the replacement write itself. If that write fails, the save and its notices both stay and the error reaches the caller.

**Launch timeout.** If the first load hasn't settled within 15 seconds, Recovery shows "Your island is taking too long to open…". The load keeps running and still publishes if it finishes. Nothing is writable until then, so nothing can overwrite the unread save.

**The Store sits above the UI boundary.** The root layout mounts `StoreProvider`, then `UIBoundary`, then the status bar and the Stack (`initialRouteName="index"`). Each screen is wrapped in its own `ScreenBoundary` through `screenLayout`. Nothing in the app remounts the Store while it runs, and no Store hands accepted state to another.

- **A screen fails:** only that screen shows "Little Island needs another try." **Try again** renders that screen again; **Back to the map** dismisses to the map. Logged as `screen`.
- **Something under the Store but above the screens fails** (the navigator itself): `UIBoundary` shows the same screen. **Try again** mounts the navigator fresh on the map, then reopens the screen the child was on if it can be rebuilt from its route name and plain string params. Failing again on the screen just reopened goes to the map instead. **Back to the map** mounts it on the map. The stack becomes map plus that screen, not the whole earlier stack. Logged as `ui` (and `ui-reopen` if reopening throws).
- In both cases the Store, its accepted state and its write queue are never touched.
- **The Store itself, or a provider around it, fails:** the root `ErrorBoundary` is `StoreFailure`, a plain restart screen with no buttons: "Little Island needs a restart. … Your saved work is kept." and how to close and reopen the app (this build has no `expo-updates`, so restarting is an instruction). It mounts no Store and writes nothing. Writes the failed Store had already accepted still drain in order; a cold start then opens the last durable save. Logged as `store`.

**Write ownership.** A Store's writes are refused once a newer Store has mounted in the same runtime, which happens only in tests. That newer Store waits for writes already running, then reads storage normally. Fast Refresh, or a development double effect, reruns the Store's hydration effect on the *same* Store with its state and refs kept. Only the first run takes ownership and hydrates. A replay keeps the accepted snapshot, its queue and its ownership; it never reads storage over them, never takes writes back from a newer Store, lets a first load that is still running finish, and keeps the launch timeout to its first deadline. Recovery reloads only through **Try opening again**.

**Save status per draft key.** Draft failures are tracked per draft key (envelope revision, owner and game). A successful draft clears only its own key, so one game's saved move never hides another game's unsaved one. Every successful full-envelope write holds every accepted move, so it clears all draft failures and a failed envelope write: the ordinary queue (including **Try saving again**), a Challenge start or finish, discarding a paused game, a Cove person change, restore, assignment of earlier work and learner removal. The error line clears only when nothing is outstanding. A refused Library change or a change refused at admission (save limit, invalid data) stays until it is resolved or a replacement (restore, assignment, removal) supersedes it. `libraryFlush()` returns true only when the queue drained with no new failure and nothing is outstanding. `backup()` waits at most 4 seconds for the queue, then exports the accepted state and says some changes could not be saved on this device.

**Launch log.** `noteLaunch` writes why launch didn't go to plan to the console, an in-memory list and an 8-entry ring on the device (`launch-log-0..7` and `launch-log-cursor`; `little-island.launch-log-*` on the web). It is never sent anywhere. `where` is one of `load`, `notices`, `set-aside`, `timeout`, `screen`, `ui`, `ui-reopen` or `store`. The ring is best effort: a note written while a save transaction is running can be lost. No save or recovery decision reads it.

## Capacity and recovery

The [measured capacity receipt](evidence/f1-save/SIZE.json) uses the actual packed formats and whole-save validator: 62,647 catalog entries, five learners including Family, four Cove-only people, maximum-size paused-session allocations, 80 Library drawings and 999,900 Library bytes. Structural test codecs measure storage; they do not establish reachability or correctness of future game engines. New Home storage and undo formats must be measured again when their owning slices land.

The 2,000,000-byte whole-save and 1,000,000-byte shared Library boundaries remain unchanged. A valid near-full legacy fixture can migrate but refuse additional dense Challenge data. Failure retains accepted state and exact originals; nothing is silently pruned. Export first, then explicitly finish or replace a selected paused game, or remove a person through grown-up management. A whole-device restore replaces every person's newer work; Previous saves is not per-child undo.

Rollback rehearsal: on the archived 3.0.x game source, envelope 3 opens recovery and remains byte-for-byte intact. Choose Start fresh there (which keeps the newer copy), then restore the exact pre-update envelope-2 Previous save. Post-update work stays only in the preserved newer copy. This source-level rehearsal passed; native Files and real-device installed-update acceptance remain separate lead checks.
