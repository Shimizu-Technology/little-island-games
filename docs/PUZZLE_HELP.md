# Whole answers, hints and puzzle endings

F4 shared kit for School, originals and Puzzle Cove. Game owners adopt these components in their own boards; the kit does not change legacy beginner engines or add games to a shelf. The public Challenge frame uses the shared ending now. Challenge boards receive optional `sessionKey` and `commit(action, expectedKey)` props; commit returns the durably accepted key and replayed state, or null. Map those to the help snapshot and callback with an explicitly redacted public view. There is no placement, clock input or automatic difficulty change.

## Whole answers

`src/puzzles/wholeAnswer.ts` keeps an editable neutral draft. Supply the real engine's `AnswerRules`: initial draft, validity, edit, completeness and acceptance. `accepts` must recognize every legitimate answer, including alternate arrangements. It must not compare only with a bank's stored witness. Edits never call `accepts`.

Render a Challenge board with `cellFeedback('whole', judge)`, which returns null without calling the judge. Beginner boards keep `cellFeedback('beginner', judge)` and their existing per-cell teaching. Technique grades still come from the engine/bank; whole-answer mode does not invent a grade.

Use `canCheckAnswer` for the Check button and call `answerCheck` only from an explicit Check action. An incomplete or repeated unchanged Check is a no-op. A miss retains every entry and records one check and miss. `last.draft` preserves the submitted draft. Editing after a miss does not reveal which cells are wrong. `WholeAnswerControls` supplies Check and neutral feedback; pass `answerMissed(state)` as `incorrect` for both it and character feedback. A new edit hides the previous verdict without judging the new draft. A sibling clears `last` while retaining the attempt’s check/miss counts.

Pass `'choice'` to `answerCheck` for option questions. A miss retires those options: edits and more Checks are blocked until `answerVariant` receives a different immutable puzzle ID on the same skill. Keep the missed draft visible until the child taps Try another. Fetch the reviewed sibling before replacing anything. Do not remove a rejected option and let the child scan the remainder. A missing sibling keeps the original draft and retired options. Return `false` from the controls’ `onVariant` callback when no reviewed sibling is available, so it displays a refusal rather than silently doing nothing. Help and the frame’s puzzle chooser/exit remain available; the shared choice kit does not provide undo.

`choiceAnswerEngine(rules, validEdit)` is the replay adapter for choice questions. Put the reviewed `{id, skill, puzzle}` sibling set in one immutable descriptor. Its derived state stores `puzzleId`, retired sibling IDs and the answer; every edit and Check resolves that ID inside the descriptor. The explicit `variant` action selects an unused same-skill sibling and retains misses in the same session. Do not start a second session to change questions. An exhausted set rejects the variant; the host must report that refusal. The real frame/Store regression covers miss → sibling → serialized pause → helped finish.

These are derived states, not a new save format. Put actions in the game's existing validated, versioned replay codec. Reject no-op edits/Checks in `ReplayEngine.step`; emit `check` with `correct` only for a new complete submission and `help` before revealing assistance. Use the existing terminal transaction to count helped finishes and preserve marks. A reset must not erase prior help/misses from the attempt's replay evidence. `tests/puzzle-whole-replay.test.tsx` shows integration with `defineReplayGame`, exact pause serialization, alternate answers and forged-result rejection.

## Four-step help

`PublicHintRules<V,A>` in `src/puzzles/hints.ts` receives **only visible facts**: visible clues/rules and the actual current draft. Construct `V` explicitly; do not pass an unredacted bank descriptor, hidden target, solution array or stored route. Declare `draft: {hasEntries, complete}` for entry grids; both predicates inspect only visible occupancy. Use `draft: null` for path/build states without entries. Look points attention; Think names an idea. Neither calls the solver nor returns an action. Their text/focus IDs must not reveal an answer. Keep content backed by the game's reviewed rules.

For One step and Show me, `problem(view)` supplies the same pure move/goal rules used by gameplay. The shared search always starts at the supplied current draft, including valid alternatives off the original route. `preserves(before, after)` must reject overwriting an already valid alternative entry; path games may allow an engine-legal undo/retrace. It is applied during search and replay verification. One step on an entry grid with any entries does not search or test them: partial drafts get the same neutral cue regardless of correctness, and filled drafts get the same Check invitation. This deliberately defers move disclosure to the explicit Show me action. On a blank grid or a path, One step applies one engine action and reports whether it finishes. A dead end or exhausted budget preserves work. It still advances the ladder to Show me; when Show me cannot complete the draft, it offers a fresh puzzle through `onFresh`. Nothing resets or substitutes a solution without a tap.

Search runs outside rendering/frame callbacks. It yields after 64 expansions or 8 ms, whichever comes first. One engine expansion must itself be bounded. The caller can abort between slices. The 8 ms bound excludes one atomic engine expansion and is not a physical-device performance claim.

`PuzzleHelp` keeps Help reachable from the start for every kind. Grids show the invitation immediately; build-and-run games additionally offer it after three failed runs. Each tap asks for the next rung: Look, Think, One step, Show me. One step applies at most one action and stops, subject to the entry-grid rule above. Show me presents the rest one move per **Next step** tap; this deliberate pacing keeps reading untimed and lets a child stop. After the demonstration it offers a fresh puzzle. No moves run from a render or timer.

Supply:

- `snapshot: {key, view}` with key containing owner, epoch, puzzle and accepted revision.
- `commit(event, expectedKey)` that checks ownership/revision, atomically records help and normal engine actions, and returns the accepted snapshot only after successful saving. Return null on rejection/I/O failure. Do not disclose a cue before that help record is accepted.
- For a `step`, apply the action through the real engine. `last` identifies a terminal One step or the final Show me action; finish a whole-answer demonstration through the same Check/result transaction so a helped finish counts. One step can also finish a puzzle and must count normally. A `finish` event asks the same engine to Check an already filled demonstration with no moves left.
- `onCue` to highlight the returned public focus IDs, and clear highlighting when null.
- `onFresh` to offer/deal a genuinely fresh puzzle of the same kind after Show me. Do not replay an answered choice question under a new session ID.
- `active=false` during blur, backgrounding, owner/epoch changes or boundary saves. Mount with a puzzle identity key. Closing help clears the board highlight. External edits reset the ladder to Look and invalidate pending hints and demonstrations; Help remains available to derive a fresh one.

The frame does not render a second Help button or record invisible assistance. Each Board renders its own ladder, and opening it alone records nothing. `ChallengeViewProps.onFresh` opens the frame’s chooser while keeping an unfinished draft available; pass it to the ladder’s fresh callback.

Replay ladder registrations declare `helpUI: 'board'` and an `assistance` reserve: maximum bytes/actions for the worst-case whole help sequence, plus `isAction` recognizing dedicated assisted-move actions and Help. The reserve must include Look/Think, One step, Show me, terminal Check/result overhead and maximum UTF-8 action size. Ordinary edits stop before spending it. Assisted actions mark the result helped during replay even if submitted without an earlier Help action. Final engine completion may spend reserved room. Each adopter must prove its own bound; the shared maze regression exhausts ordinary edits, then completes help through the real frame/Store. Legacy registrations reserve 512 bytes/16 actions for basic Help only. Repeated Help checkpoints advance the guarded revision and await saving without appending redundant help actions; a repeated Look/Think cannot fill the audit log. The codec admits these identical-payload revisions only after help is already replay-proven.

The component uses the game's commit callback for every effect. It catches unavailable/error states and keeps the draft. It cannot make an unsafe host callback safe: hosts must enforce the expected key and use the existing validated save path. Tests exercise rejected saves, rapid taps, owner switches, stale results and normal revision updates.

## First open and quiet endings

`PickYourTide` takes three real small puzzle samples, labeled Shallow, Middle and Deep by the host. A tap selects that sample without recording placement. Persist only the ordinary explicit choice if needed, never an inferred ability. School keeps its existing beginner opening; use this first-open chooser for new original/Cove games.

`PuzzleEnding` gives Easier, Same and Harder the same size and weight. Try another invokes its callback once with one tap. `adjacentTide` rotates through the whole selected tier, preferring cards absent from the saved `progress.recent` list and then its oldest card. Directions use the nearest available band within the selected path. A one-card tier opens the chooser instead of redealing the same card. At a band boundary, open the full chooser; do not auto-move the player. The Challenge frame starts its replay through normal save guards and clears the previous puzzle's dare selection.

Supply specific praise from the real outcome, such as “You used both clues to seat the friends.” Replay registrations can provide `completionText(ref, result)` and must distinguish helped/Together outcomes from independent work. The generic fallback describes completion honestly, including help; specific game praise remains the adopter’s responsibility. Personal offers replace the direction row, and dismissing a card consumes that round’s prompt. Disabling offers or enabling the young-child option hides the direction prompts and keeps plain Try another and Back. Finished screens omit the extra Another puzzle and Easier choice actions. Failure lines come from the character through `PuzzleFeedback`; the board uses `PuzzleFailure.focus` to highlight the failing step. Do not use that highlight to reveal per-cell correctness in whole-answer mode.

Original-game hosts call `finishOriginalPuzzle` once per distinct completed attempt and use `originalRoundDone` to stop after four. Use an attempt ID, since revisiting the same bank puzzle is still a separate attempt. Skipping records no finish. A helped solve counts. Pass `roundDone` to the ending; a new round requires a new explicit action. Save this round state through the game's validated session codec, with original data preserved on recovery.

## Verification fixture

`tests/native/puzzle-kit.tsx` is a standalone Expo entry for native QA, absent from app routes/registries. It exercises real shared controls with a visible “make five” puzzle and multiple accepted answers. It has memory-only fixture state, so it is not persistence acceptance. The F2 replay tests cover serialization and result validation separately. Build it with `expo export:embed --entry-file tests/native/puzzle-kit.tsx` into an isolated simulator app, never a family artifact.

The native fixture’s actual `publicSumView` builder is tested with varied hidden solution/private records for all four rungs and with a changed public target. This proves only that adapter’s boundary. Every other adopter needs its own real view-builder permutation test; the shared type alone cannot prove redaction.

Full game-specific native journeys, real-device search timings, VoiceOver operation, family acceptance and each future adapter's public-information audit remain their track/lead gates.
